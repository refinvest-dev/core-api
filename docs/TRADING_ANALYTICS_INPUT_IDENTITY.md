# Trading Analytics Input Identity V1

This document is the canonical Core→Compute semantic input contract. See [the job protocol](TRADING_ANALYTICS_JOB_PROTOCOL.md), [result integrity](TRADING_ANALYTICS_RESULT_INTEGRITY.md), and ADR-069 in [DECISIONS](DECISIONS.md). All JSON hashes below use RFC 8785 JCS over UTF-8, without BOM, whitespace or final newline. Duplicate object keys, noncanonical decimal strings, unsafe JSON integers, and unsupported schema versions fail before calculation. Do not normalize Unicode. SHA-256 is lowercase hexadecimal. Array order is specified below; object property order is JCS order.

## Two immutable Core artifacts

The existing `ledgerRevisionContent` and `reconciliationManifest` `CorePayloadReference`s each pin `coreReferenceId`, `mediaType`, positive `byteSize`, `sha256`, `accessUri`, and `expiresAt`. Byte size and SHA-256 describe the exact downloaded entity body. Locator/expiry are grants, never content identity. Each grant is read-only, bound to the logical job, Run, role, attempt, and deletion generation, expires within five minutes, and is never logged. The Core publishes both artifacts before dispatch and never mutates bytes at an existing `coreReferenceId`.

`ledgerRevisionContent` has media type `application/vnd.refinvest.trading-analysis-input.v1+json` and root `AnalyticsLedgerInputV1`: `schemaVersion=TRADING_ANALYTICS_LEDGER_INPUT_V1`, `ledgerRevisionId`, `ledgerContentHash`, `canonicalSchemaVersion`, `reviewUnitSchemaVersion`, `instrumentDescriptors`, `canonicalRecords`, `sourceEvidenceReferences`, `reviewUnitEngineInputs`. The descriptors use pinned instrument terms plus `sourceSymbol`; one per referenced instrument ID. `canonicalRecords` are the public `CanonicalTradingRecord` union, sorted by `recordId`, with record IDs and hashes from the published Revision. `sourceEvidenceReferences` are `{snapshotId,recordId,coreArtifactId,sourceRowNumber,sourceRowHash}` sorted by `(recordId,snapshotId)`; they point to Core's retained masked source evidence, without raw CSV or user ID. A canonical record's `sourceEvidenceSnapshotId` must resolve to a row in this array for that record. `reviewUnitEngineInputs` is sorted by `reviewUnitId` and contains exactly one supplementary row per manifest ReviewUnit: its direct `evidenceRecordIds`, `stableEpisodeTimeAvailable`, and sorted `allocationEvidence={allocationId,evidenceRecordIds,allocatedFee,allocatedReportedPnl}` for every allocation. Fee/PnL amounts are the normalized allocation outputs, including real zero amounts with pinned currency; Core must not synthesize missing values. This preserves Engine input fields absent from the public Normalization ReviewUnit projection without duplicating a full ReviewUnit. Core must retain these verified fields in the immutable Revision at publication; a historical Revision without them is incompatible and cannot be silently analyzed. `ledgerContentHash` equals the Normalization `CANONICAL_RECORDS` section hash (same projection in V1 and V2), independently recomputed from sorted public canonical records under its pinned hash specification. It is not a hash of this whole Analytics artifact.

`reconciliationManifest` has media type `application/vnd.refinvest.trading-reconciliation-manifest.v1+json`. Its root is exactly the published `ReconciliationManifestPayload`, including `reviewUnits`, allocations, capability and required counts. Do not copy ReviewUnits into the ledger artifact. Its `manifestHash` is independently recomputed by removing **only** `manifestHash` from the received manifest and hashing the remaining complete object per [Normalization result integrity](TRADING_NORMALIZATION_RESULT_INTEGRITY.md). This does not change the Normalization V1 vector.

Compute joins each manifest ReviewUnit to its supplementary engine row by `reviewUnitId`, each allocation to its supplementary row by `allocationId`, and records to source references by `recordId`/`sourceEvidenceSnapshotId`. For an Engine `ScaledDecimal`, the public `value` and `sourceScale` produce the exact plain decimal lexeme padded to that scale; reject an unrepresentable pair. The pinned instrument `contractMultiplier` decimal string is its Engine lexeme and value. Evidence rows use `(coreArtifactId,sourceRowNumber,sourceRowHash)` from source references; never invent a missing row. `stableEpisodeTimeAvailable` and allocated fee/PnL come from the supplementary rows and must agree with manifest capabilities and any non-null public allocation amount. A missing supplementary row or discrepancy is `EVIDENCE_REFERENCE_INVALID`/`INPUT_SCHEMA_UNSUPPORTED`, not a zero/default. This is the lossless adapter from the two public artifacts to the current `calculate_behavior_metrics` arguments.

Compute verifies exact byte size/SHA-256 for both artifacts before parsing; rejects duplicate JSON keys; validates both roots; checks request/ledger `ledgerRevisionId`; recomputes `ledgerContentHash` and `manifestHash`; checks every ReviewUnit and allocation's canonical record ID, instrument descriptor, supplementary engine input and source evidence reference; checks request capability snapshot exactly against manifest capability; checks ReviewUnit schema against each selected Metric definition; and checks config and exact VersionSet compatibility. A request capability snapshot is an admission hint, never authority over downloaded contents. Mismatch is a failed job without a completed result.

## AnalysisConfig identity

`analysisConfigHash = lowercaseHex(SHA-256(UTF-8(JCS(InternalAnalysisConfig))))`. The exact root is the OpenAPI `InternalAnalysisConfig`; **all** fields are required and non-null: `schemaVersion=1`, `analysisPeriod={startInclusive,endExclusive}`, `reviewTimezone`, `timezoneDatabaseVersion`, `outcomeBasis=NET_TRADING_PNL`, `fundingTreatment=EXCLUDED`, `eligibleReviewUnitPolicy=COMPLETE_AND_RECONCILED_ONLY`, `reversalTreatment=SEPARATE`, `reentryWindow=PT30M`, `baselinePolicy=PRIOR_PERIOD_SAME_INSTRUMENT_DIRECTION`, `metricMinimums={reentryEligibleLosses,exposurePairs,priorBaselineEpisodes,holdingWins,holdingLosses}`, and `findingMinimums={reentryEligibleLosses,exposurePairs,holdingWins,holdingLosses}`. All minimums are positive safe integers. Period endpoints are UTC `YYYY-MM-DDTHH:mm:ss[.ffffff]Z`, with no unnecessary fractional trailing zeros, and start < end. `reviewTimezone` is a pinned IANA name; its exact case and the pinned tzdb version are hashed. There are no default omissions. A semantic change requires a new `analysisConfigVersion` in `targetVersionSet` and a new schema version where the root changes.

## Analytics semantic input hash

`TRADING_ANALYTICS_INPUT_HASH_V1` hashes exactly the following `AnalyticsInputIdentityV1` root, with every property required:

```json
{"hashSpecificationVersion":"TRADING_ANALYTICS_INPUT_HASH_V1","ledgerRevisionId":"…","ledgerRevisionContent":{"coreReferenceId":"…","mediaType":"application/vnd.refinvest.trading-analysis-input.v1+json","byteSize":1,"sha256":"…"},"reconciliationManifest":{"coreReferenceId":"…","mediaType":"application/vnd.refinvest.trading-reconciliation-manifest.v1+json","byteSize":1,"sha256":"…","manifestHash":"…"},"ledgerContentHash":"…","analysisConfigHash":"…","targetVersionSet":{},"capabilitySnapshot":[]}
```

The shown placeholders are illustrative; the OpenAPI `AnalyticsInputIdentityV1` and [fixed vector](../fixtures/trading-analytics/input-identity-v1.json) give valid values. `targetVersionSet` is the **entire** exact `InternalAnalyticsVersionSet`, including its nested Metric versions, Finding rule version and hashes. `capabilitySnapshot` is deduplicated and sorted by enum wire value. All other arrays in the two input artifacts use their schema-specific stable order; do not reorder opaque source arrays when checking artifact bytes. `analysisInputHash`/`expectedInputHash` is the lowercase SHA-256 of the JCS root above.

The projection excludes `accessUri`, `expiresAt`, job ID, Core logical job ID, Core Run ID, attempt token, deletion generation, retry/delivery policy, lease, and every execution timestamp. Changing these cannot change `analysisInputHash`. Changing artifact bytes, reference identity, config, capability or exact VersionSet must change it. Create carries both `inputIdentity` and the top-level grants/config/version declarations. Compute checks every duplicated stable artifact field, LedgerRevision ID, config hash, VersionSet and capability against the identity root, then independently hashes that root before claiming work; a disagreement fails `INPUT_HASH_MISMATCH` or `ANALYSIS_CONFIG_HASH_MISMATCH` without fetching. Core performs the same check before dispatch. `analysisLogicalKey` remains a separate Core orchestration key and is never compared as if it were `analysisInputHash`.

Three independent identities remain distinct: semantic input is this hash; runtime identity is `(jobId,coreLogicalJobId,coreAnalysisRunId,attemptToken,deletionGeneration)`; transport identity is `(payloadId,mediaType,contentEncoding,byteSize,payloadSha256,expiresAt)`. A hash equality never substitutes for a runtime-current or byte check.

## Normalization V2 provenance of engine inputs

ADR-070 adds `analyticsInputSupplement` to the Normalization V2 terminal result and immutable LedgerRevision. Its `reviewUnitEngineInputs` rows have exactly the fields already required by `AnalyticsLedgerInputV1.reviewUnitEngineInputs`; Core copies the independently verified stored rows in their specified order. The public `ReconciliationManifestPayload`, its V1 hash projection, both Analytics artifact media types, `AnalyticsLedgerInputV1` root, and `TRADING_ANALYTICS_INPUT_HASH_V1` projection remain unchanged. `ledgerContentHash` for V2 uses the unchanged `CANONICAL_RECORDS` section projection. The Analytics input artifact's bytes and SHA-256 pin the copied supplement, so a difference also changes `analysisInputHash`. Core must not derive absent evidence or money from records or assign zero. A historical Revision without the supplement fails Core admission with public `422 ANALYTICS_INPUT_UNAVAILABLE`, before artifact creation or Compute dispatch; explicit compatible reconstruction creates a new Revision instead of editing the old one.
