# Trading Analytics Job Protocol V1

ADR-069 selects this protocol. The [input identity](TRADING_ANALYTICS_INPUT_IDENTITY.md), [result integrity](TRADING_ANALYTICS_RESULT_INTEGRITY.md), and [delivery](TRADING_ANALYTICS_RESULT_DELIVERY.md) documents are normative, together with `openapi/compute-api.yaml`. This is an internal Core→Compute contract; Web only calls Core.

Core admits a Revision to this protocol only if its independently verified, immutable Normalization V2 `analyticsInputSupplement` is stored. A historical Revision without it returns public `422 ANALYTICS_INPUT_UNAVAILABLE` before Run/job or Analytics artifacts are created. This is a Core admission failure, not an Analytics Compute job failure. See [Normalization result integrity](TRADING_NORMALIZATION_RESULT_INTEGRITY.md) and ADR-070.

## Ownership and state

Core owns the immutable LedgerRevision, AnalysisConfig, TradingAnalysisRun, deletion tombstone/generation, publication transaction, long-lived AnalysisResult and ACK outbox. Compute owns the durable job, grant revision, attempt/lease, bounded transient input and terminal payload, and failure metadata. Core pins the exact artifacts, semantic hash, Analytics VersionSet, attempt token, deletion generation, retry policy and delivery limit before create. Compute never changes these semantic pins. The Core `analysisLogicalKey` is its own orchestration/idempotency key; Compute independently calculates `analysisInputHash`.

The API sequence is create (`POST /trading-review/analytics-jobs`, `Idempotency-Key`), poll (`GET .../{jobId}`), optional input grant update (`POST .../{jobId}/input-grants`), optional cancellation (`POST .../{jobId}/cancellation`), terminal descriptor (`GET .../{jobId}/result`), one payload download (`GET /trading-review/terminal-payloads/{payloadId}`), then ACK (`POST /trading-review/jobs/{jobId}/acknowledgement`). Only `COMPLETED` has a result descriptor/payload. `PENDING→RUNNING→COMPLETED|FAILED|CANCELLED`; `PENDING→FAILED|CANCELLED` is allowed. A terminal job cannot transition again or accept grant updates. A durable worker claim increments lease generation and sets a finite lease expiry. A worker may commit a result only by comparing job ID, current attempt token, lease generation, and deletion generation atomically; a lost lease, replaced attempt, or deleted generation cannot publish a payload. Lease renewal is conditional on these same identities. Polling exposes identity, grant revision, attempt number, state, safe failure, and terminal payload ID/hash when complete. A restarted worker reclaims an expired lease on the **same** attempt only when no attempt failure has been committed; committed retryable failure requires Core to start a new attempt. This prevents two valid terminal writers.

Create fingerprint is JCS of `{coreLogicalJobId,coreAnalysisRunId,ledgerRevisionId,ledgerRevisionContent:{coreReferenceId,mediaType,byteSize,sha256},reconciliationManifest:{coreReferenceId,mediaType,byteSize,sha256},inputIdentity,expectedInputHash,inputHashSpecificationVersion,analysisConfig,analysisConfigHash,targetVersionSet,capabilitySnapshot,resultSchemaVersion,resultHashSpecificationVersion,attemptToken,deletionGeneration,retryPolicyVersion,resultDeliveryPolicy}`. It excludes both locators/expiries. A newly accepted create returns `202 TradingAnalyticsJobAccepted` (`PENDING`, attempt 1, grant revision 0). The same idempotency key and fingerprint returns `200 TradingAnalyticsJobStatusResponse` with the existing job's **current** `PENDING`, `RUNNING`, `COMPLETED`, `FAILED`, or `CANCELLED` state, including its current attempt and grant revision; a different fingerprint returns 409. A replay does not change grants, attempt, capacity reservation, or job state, even when the supplied locators/expiries differ or the job has since been updated. Same reference ID with different bytes is `ARTIFACT_IDENTITY_CONFLICT`. Capacity rejection creates no job or idempotency record and returns 503 with `Retry-After`; existing create replays are resolved before capacity admission.

## Grants, retry and deletion

`ANALYTICS_RETRY_V1`: maximum three attempts including initial; only Core initiates retry, within 24 hours of job creation and before deletion/Run terminal publication. A retryable failure consumes an attempt even if no worker started. No hidden Compute retry after a committed failure. A worker lease lasts `PT60S` and is renewed at least once per `PT20S` while work continues; renewal and terminal commit use the current lease generation CAS. Core uses bounded backoff 1s, 2s, 4s (plus bounded jitter at most 250ms), capped by the creation cutoff and grant expiry; 503 admission retry does not consume an accepted job attempt. Terminal failed jobs are not resurrected: a retryable attempt failure is represented as `PENDING` with `lastAttemptFailure` and `retryAvailable=true` until Core's `START_RETRY_ATTEMPT`; when cutoff/budget expires Compute commits `FAILED` with `RETRY_EXHAUSTED`. A nonretryable failure commits `FAILED` immediately. Core may also stop retrying and mark its Run failed; cancellation is best effort and never revokes deletion precedence.

Input grant updates have their own `Idempotency-Key` and conditional `expectedGrantRevision`, `expectedAttemptToken`, `expectedInputHash`, `versionSetHash`, `deletionGeneration`, and `expectedRetryCutoffAt` (the status value, exactly job `createdAt + PT24H`). The update fingerprint is SHA-256/JCS of the **entire** update body, including both locators and expiries; only its digest is kept in the idempotency record. `REPLACE_QUEUED_GRANTS` requires `PENDING`, no active claim and **no committed failure for the current attempt**; it replaces both fresh, unconsumed artifact locators/expiries while maintaining artifact identities and attempt token, then increments grant revision. `START_RETRY_ATTEMPT` requires a committed retryable attempt failure and available budget/cutoff; it requires a distinct `nextAttemptToken`, retains semantic/config/version identities, accepts two fresh grants, marks prior worker/output stale, increments attempt and grant revision, and returns `PENDING`. Requests whose expected revision/token/generation/cutoff are stale return 409. Same update key and fingerprint returns the first receipt; a reused key with different fingerprint returns 409. Already terminal jobs reject updates. Grants are valid at claim and during fetch; expiry before/during fetch is `INPUT_REFERENCE_EXPIRED` or `INPUT_STREAM_ABORTED`, never silent renewal by create replay.

Core increments deletion generation and persists a tombstone before cancelling outstanding work. A result with a past generation or attempt is stale even when semantic and transport hashes match. Core never publishes it; if a completed payload is still available it sends `DISCARDED_STALE`, otherwise records stale discard locally. A current completed result is streamed and verified, then Core atomically commits AnalysisResult and Run `COMPLETED` under compare-and-set of Run, attempt and generation, and only then sends `PERSISTED` from its durable ACK outbox. An ACK timeout retries the **same** ACK, never publication. Identical ACK replay is no-op; changed job/attempt/generation/hash or disposition returns 409. Deletion takes precedence over retry and publication. No result is published from FAILED/CANCELLED.

## Safe failures

The public code is a stable enum; logs contain only job ID, Run ID, attempt number/token digest, generation, artifact role, expected/actual byte counts or hash *prefixes*, version identifiers, and safe failure code. Never log locator, raw rows, account ID, source value, signed query or full hash of private evidence. `MISSING_CAPABILITY`, `INSUFFICIENT_SAMPLE`, `NOT_APPLICABLE`, a real numeric zero and zero Findings are **COMPLETED Metric states**, never job failures.

The table's pending retry state is a durable job in `PENDING` with committed failed attempt metadata. Core Run remains `RUNNING` while retry is possible; it becomes `FAILED` only on terminal failure. Safe code `MISSING_CAPABILITY` remains a Metric status and is not emitted as job failure. Retention: input spool is purged after attempt/cancel and at latest terminal plus `PT24H`; completed payload expires at `terminalAt + PT24H` at latest, or earlier after ACK. Compute job metadata and minimal idempotency/ACK receipt are purged by terminal plus `PT24H` or sooner on deletion; Core durable Run/outbox retains the long-term audit under its own lifecycle. No raw rows or locators are retained in logs. Core orphan result spool is purged by a sweeper within `PT24H` even after crash. See [data lifecycle](TRADING_DATA_LIFECYCLE.md) for deletion SLA.
