# Trading Analytics Result Delivery V1

`ANALYTICS_RESULT_DELIVERY_V1` delivers one bounded resource. See [job protocol](TRADING_ANALYTICS_JOB_PROTOCOL.md), [result integrity](TRADING_ANALYTICS_RESULT_INTEGRITY.md), ADR-069 and `openapi/compute-api.yaml`.

Create pins `resultDeliveryPolicy={policyVersion:ANALYTICS_RESULT_DELIVERY_V1,transportMode:SINGLE_RESOURCE,maxPayloadBytes:<positive safe integer>}`. Core advertises the maximum it can receive; Compute enforces `min(advertised maxPayloadBytes, its positive configured max)`. Compute serializes the **whole** completed payload first into a bounded spool, and fails `RESULT_PAYLOAD_TOO_LARGE` if the next byte would exceed the effective cap. It never truncates, paginates or emits a partial success. Changing the cap requires a new create fingerprint/Run, not an in-place retry.

The payload endpoint returns `application/vnd.refinvest.trading-analytics+json`, UTF-8 without BOM, `Content-Encoding: identity`, no compression, byte ranges, pagination or chunks at the application level. HTTP transfer framing may stream; descriptor `byteSize` and `payloadSha256` cover exactly the response entity body bytes, excluding HTTP headers, transfer framing and TLS. A 200 response must use that media type and identity encoding. `Content-Length` may be omitted; Core counts actual streamed bytes. Core streams to a private bounded spool, aborts immediately beyond the negotiated cap, checks descriptor size and SHA-256 before JSON parsing, and deletes the spool after a verified commit or safe failure. The spool cannot be exposed as an API or retained as a long-term AnalysisResult. A transient interrupted download may be retried while the same unexpired payload is available; descriptor identity and bytes must remain identical.

`AnalyticsTerminalResultDescriptor` is Analytics-specific: job ID, Core logical job and AnalysisRun IDs, payload ID, transport mode, delivery policy version, media type, content encoding, byte size, payload SHA-256, attempt token, deletion generation, input hash/spec, AnalysisConfig hash, exact target VersionSet, result schema/hash versions, structural counts, section digests, evidence hash, result hash, createdAt and expiresAt are required. All corresponding terminal payload identities, counts and hashes must match the descriptor. `expiresAt` is after terminalAt and no later than `terminalAt + PT24H`. Compute may purge after ACK; after expiry it returns 404 or 410 with safe `RESULT_PAYLOAD_EXPIRED`, never a different payload under the same ID.

Core sends `PERSISTED` only after durable AnalysisResult publication commit. It sends `DISCARDED_STALE` for a completed result rejected by stale attempt or increased deletion generation and records the stale reason and current identity. Both ACKs include `coreAnalysisRunId`, `payloadId`, `payloadSha256`, `terminalResultHash`, `attemptToken`, `deletionGeneration`, and `disposition`; stale ACK also has `currentDeletionGeneration` when deletion caused staleness, or `currentAttemptToken` when an attempt changed. Core may discard from a verified descriptor without downloading stale bytes; it must check descriptor job/Run identity before ACK. Same ACK replay is idempotent; changed identity/hash/disposition is 409. ACK failure only retries the ACK from Core outbox. Compute can purge bytes after ACK but keeps a bounded receipt/tombstone for duplicate ACK validation. If retrying an already committed Core outbox ACK reaches 404/410 after the pinned `expiresAt`, Core records `ACK_RESOURCE_EXPIRED` and closes the outbox item without republishing; a 404 before expiry or any 409 remains an incident requiring investigation. Failed/cancelled jobs have no payload and no ACK.

V2 is required for compression, multipart, pagination, chunk indexes, resumable range, or a result larger than the negotiated V1 cap. Those changes must use a new policy version and explicit schema/hash rules; V1 clients must fail unsupported policy rather than guess.
